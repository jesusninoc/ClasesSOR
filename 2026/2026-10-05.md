# Cuentas y grupos

## 1.1. Usuarios y grupos locales

**Explicar:**
- La administración del servidor comienza por controlar quién puede acceder.
- Cada persona o servicio tiene una **cuenta de usuario**.
- Los usuarios se organizan en **grupos** para asignar permisos de forma colectiva.
- Diferenciar:
  - Administrador.
  - Usuario estándar.
  - Cuenta de servicio.
  - Invitado.
- Diferenciar **grupos locales** y **grupos de dominio**.

**Windows Server:**
- Administración de equipos → Usuarios y grupos locales.
- También mediante comandos.

**Linux:**
- `/etc/passwd` → cuentas.
- `/etc/group` → grupos.
- Comandos principales: `useradd`, `passwd`, `groupadd`, `usermod`.

**Idea clave:**
> Los permisos se asignan al grupo y después se añaden usuarios al grupo.

**Preguntar:**
- ¿Por qué es mejor dar permisos a un grupo que a cada usuario?
- ¿Dónde se almacenan los usuarios en Linux?
- ¿Qué diferencia hay entre un grupo local y uno de dominio?

## 1.2. Perfiles, contraseñas y políticas

**Explicar:**
- El perfil contiene la configuración y datos del usuario.
- Tipos principales:
  - Perfil local.
  - Perfil móvil o roaming.
- Las contraseñas deben estar protegidas mediante políticas.

**Políticas importantes:**
- Longitud mínima.
- Complejidad.
- Caducidad.
- Historial.
- Bloqueo tras varios intentos fallidos.
- Restricciones de acceso.

**Idea clave:**
> Una cuenta segura no depende solo de una contraseña: depende también de las políticas que controlan esa cuenta.

**Preguntar:**
- ¿Qué problema resuelve un perfil móvil?
- ¿Qué ocurre después de varios intentos de contraseña incorrectos?
- ¿Por qué no conviene permitir contraseñas débiles?

## 1.3. Propiedades de una cuenta de usuario

**Explicar que una cuenta tiene muchas más propiedades que usuario + contraseña:**

- Nombre de inicio de sesión.
- Nombre completo y descripción.
- Contraseña y sus opciones.
- Cuenta habilitada/deshabilitada.
- Fecha de caducidad.
- Horas permitidas de inicio de sesión.
- Equipos desde los que puede iniciar sesión.
- Perfil y carpeta personal.
- Grupos a los que pertenece.

### Concepto especialmente importante: identificador de seguridad

**Remarcar:**
- El sistema identifica internamente la cuenta mediante un identificador único.
- El nombre de usuario no es lo que determina sus permisos.
- Si se borra una cuenta y se crea otra con el mismo nombre, **no es la misma cuenta**.
- Por eso, ante una baja normalmente es mejor **deshabilitar** antes que borrar.

### Diferenciar

- **Deshabilitar:** impide el acceso, pero conserva la cuenta.
- **Caducar:** deja de funcionar a partir de una fecha.
- **Borrar:** elimina la cuenta y su identificador.

**Preguntar:**
- ¿Qué harías con la cuenta de un trabajador que deja temporalmente la empresa?
- ¿Qué diferencia hay entre deshabilitar y borrar?
- Si creo otra cuenta con el mismo nombre, ¿recupera automáticamente los permisos de la anterior?

**Linux:**
- `/etc/passwd` → información básica.
- `/etc/shadow` → contraseñas y caducidad.
- `/etc/group` → grupos.
- `id` → grupos e identificadores.
- `chage` → caducidad de contraseñas.
- `usermod -L` → bloquear.
- `usermod -U` → desbloquear.

## 1.4. Plantillas de cuentas y valores predeterminados

**Explicar el problema:**
- Crear muchas cuentas manualmente provoca errores e inconsistencias.

**Solución:**
- Utilizar **plantillas de cuentas**.
- La plantilla contiene las características comunes.
- Se copia para crear cada usuario.

**Una plantilla puede definir:**
- Grupos.
- Opciones de contraseña.
- Horarios.
- Rutas del perfil.
- Carpeta personal.
- Descripción.
- Caducidad.

**No se hereda:**
- Nombre del usuario.
- Nombre de inicio de sesión.
- Contraseña.
- Identificador de seguridad.
- Estado final de la cuenta.

### Linux

**Tres elementos que deben conocer:**

- `/etc/skel` → archivos que se copian al crear la carpeta personal.
- `/etc/default/useradd` → valores predeterminados de `useradd`.
- `/etc/login.defs` → políticas generales de cuentas.

**Idea clave:**
> La plantilla define cómo debe ser una cuenta; un script puede encargarse de crear muchas cuentas.

**Preguntar:**
- ¿Qué ventaja tiene una plantilla frente a crear cada cuenta desde cero?
- ¿Qué contiene `/etc/skel`?
- ¿Se comparte el identificador de seguridad entre las cuentas creadas desde una plantilla?

## 1.5. Tipos de perfiles y planificación de perfiles móviles

**Explicar los cuatro tipos:**

- **Local:** permanece en el equipo.
- **Móvil:** se almacena en el servidor y permite utilizar el mismo entorno en diferentes equipos.
- **Obligatorio:** perfil móvil cuyos cambios no se conservan.
- **Temporal:** aparece cuando el sistema no puede cargar correctamente el perfil.

### Perfil móvil

**Explicar su funcionamiento:**

1. El usuario inicia sesión.
2. El perfil se copia desde el servidor.
3. El usuario trabaja.
4. Al cerrar sesión se sincronizan los cambios.

**Problemas que hay que prever:**
- Tamaño del perfil.
- Espacio necesario en el servidor.
- Permisos.
- Ubicación de los perfiles.
- Cuotas.
- Velocidad de la red.

**Remarcar:**
- Los documentos no deberían almacenarse dentro del perfil móvil.
- Se pueden redirigir carpetas como Documentos o Escritorio.
- Perfiles demasiado grandes provocan inicios y cierres de sesión lentos.
- No son adecuados para equipos con conexiones lentas o que salen habitualmente de la organización.

**Incidencias típicas:**
- Inicio de sesión lento → perfil demasiado grande.
- Perfil temporal → problemas de permisos, espacio o acceso al perfil.
- El usuario no encuentra su configuración → ruta del perfil incorrecta.

**Preguntar:**
- ¿Qué diferencia hay entre perfil local y móvil?
- ¿Qué ocurre con los cambios en un perfil obligatorio?
- ¿Por qué un perfil móvil demasiado grande es un problema?
- ¿Por qué no debemos guardar los documentos dentro del perfil móvil?

# Ejemplo práctico: usuarios y grupos

## Contexto

Empresa con tres departamentos:

- Administración.
- Ventas.
- Técnicos.

## Explicar la solución

- Crear una cuenta para cada persona.
- Crear un grupo por departamento.
- Añadir cada usuario al grupo correspondiente.
- Aplicar políticas de contraseñas.
- Reservar la cuenta de administrador para tareas administrativas.

## Idea clave

> Primero organizamos usuarios y grupos; después utilizaremos esos grupos para asignar permisos.

## Preguntas para la clase

- ¿Crearías un grupo por persona?
- ¿Dónde pondrías a un usuario que pertenece a dos departamentos?
- ¿Darías permisos directamente a cada usuario?
- ¿Qué ventajas tiene utilizar grupos?
- ¿Qué cuenta debería utilizarse para trabajar habitualmente: administrador o usuario estándar?

# Ideas que deben quedar claras al terminar

1. **Usuario = identidad.**
2. **Grupo = conjunto de usuarios con permisos comunes.**
3. **Los permisos se gestionan preferentemente mediante grupos.**
4. **Deshabilitar no es borrar.**
5. **Caducar no es borrar.**
6. **Una cuenta nueva con el mismo nombre no recupera la identidad de la antigua.**
7. **Las políticas de contraseña protegen las cuentas.**
8. **Las plantillas permiten crear cuentas homogéneas.**
9. **En Linux hay que conocer `/etc/passwd`, `/etc/shadow`, `/etc/group` y `/etc/skel`.**
10. **Los perfiles móviles permiten mantener el entorno del usuario entre distintos equipos, pero requieren planificación.**
11. **El perfil móvil no debe utilizarse como almacén de documentos.**
12. **La administración correcta de usuarios y grupos será la base para trabajar posteriormente con permisos.**
