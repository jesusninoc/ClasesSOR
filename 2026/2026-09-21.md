# 1. Planificación de la instalación

---

# 2. Particionado

Particionar = **dividir el disco en zonas independientes**.

En servidores interesa separar:

- Sistema.
- Datos.

Así, si una zona se llena, no necesariamente deja sin espacio al sistema.

---

# 3. MBR y GPT

### MBR
- Esquema clásico.
- Asociado a BIOS.
- Hasta cuatro particiones primarias.
- Limitación de discos de 2 TB.

### GPT
- Esquema actual.
- Asociado a UEFI.
- Sin las limitaciones prácticas de MBR.
- Mantiene una copia de la tabla al final del disco.
- Es el utilizado actualmente en servidores.

---

# 4. UEFI y partición EFI

Con **UEFI + GPT** aparece la:

> **Partición del sistema EFI**

- Pequeña.
- FAT32.
- Contiene los cargadores de arranque.
- No se utiliza para datos.

---

# 5. Ejemplo de reparto del material

Para un disco de 240 GB:

| Partición | Tamaño |
|---|---:|
| EFI | 0,5 GB |
| Sistema operativo | 60 GB |
| Intercambio/paginación | 8 GB |
| Datos | 160 GB |
| Sin asignar | 11,5 GB |

El espacio sin asignar puede mantenerse como **reserva para futuras ampliaciones**.

# 6. Sistemas de archivos

### Windows

**NTFS**
- Permisos por usuario y grupo.
- Cifrado.
- Cuotas.
- Registro por diario.
- Elección por defecto en un servidor Windows.

**ReFS**
- Orientado a volúmenes grandes de datos.
- Comprobación de integridad.
- No sustituye a NTFS para el disco del sistema.

### Otros

**FAT32 / exFAT**
- Alta compatibilidad.
- Sin permisos adecuados para un servidor.
- FAT32 limita el tamaño de archivo a 4 GB.
- FAT32 aparece en la partición EFI y medios extraíbles.

**ext4**
- Habitual en Debian y Ubuntu.
- Estable.
- Registro por diario.

**XFS**
- Habitual en distribuciones de la familia Red Hat.
- Buen rendimiento con archivos y volúmenes grandes.

# 8. Comprobación y preparación de discos en Linux

```bash
lsblk -f
sudo parted /dev/sdb mklabel gpt
sudo parted -a opt /dev/sdb mkpart datos ext4 0% 100%
sudo mkfs.ext4 -L DATOS /dev/sdb1
sudo blkid /dev/sdb1
sudo mkdir -p /srv/datos
sudo mount /dev/sdb1 /srv/datos
```

Para montaje permanente:

```text
UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /srv/datos ext4 defaults,nofail 0 2
```

> En `/etc/fstab` se utiliza el **UUID**, no el nombre `/dev/sdb1`.

# 9. Selección de componentes

Principio:

> **instalar solo lo necesario.**

Ventajas:
- Menor consumo.
- Menor superficie de ataque.
- Menos componentes que actualizar.

---

# 10. Windows Server

Dos experiencias:

### Instalación mínima / Server Core
- Sin escritorio.
- Menor consumo.
- Menor superficie.
- Administración por línea de comandos o remoto.

### Experiencia de escritorio
- Interfaz gráfica.
- Más cómoda para aprender.
- Mayor consumo.

### Roles
Ejemplos:
- Servidor de archivos.
- Servidor de impresión.
- Servicios de dominio.
- Servidor web.

### Características
- Herramientas de administración.
- Clientes de protocolos.
- Copias de seguridad.

```powershell
Get-WindowsFeature
Install-WindowsFeature -Name FS-FileServer -IncludeManagementTools
Uninstall-WindowsFeature -Name Print-Services
```

---

# 11. Linux server

La lógica es equivalente:

- Sistema base.
- Servicios necesarios.
- Paquetes adicionales.

```bash
sudo apt update
sudo apt install --no-install-recommends openssh-server
systemctl is-enabled ssh
sudo systemctl disable --now cups
```

> Instalar los servicios uno a uno y comprobarlos.

# 14. Configuración inicial

### Red
- IP estática.
- Puerta de enlace.
- DNS.

### Sistema
- Nombre definitivo.
- Zona horaria.
- Idioma.

### Seguridad
- Contraseña fuerte.
- Cortafuegos.
- Deshabilitar lo innecesario.

### Actualizaciones
Aplicar actualizaciones de seguridad.

Linux:

```bash
sudo apt update && sudo apt upgrade -y
```
