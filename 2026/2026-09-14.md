## 2. ¿Qué es un sistema operativo en red?

Un **SO en red** está pensado para **dar servicio a una red de equipos**.

### Funciones
- Gestión centralizada de usuarios.
- Recursos compartidos: archivos e impresoras.
- Servicios: web, correo, bases de datos.
- Seguridad.

### Diferencias respecto a un SO de escritorio
- Mayor estabilidad.
- Rendimiento con muchos usuarios.
- Orientación a servicios.
- Mayor atención a la seguridad.
- Puede funcionar sin interfaz gráfica.

### Ejemplos
- **Windows Server** → propietario.
- **Linux server** → libre.

---

## 3. Modelos de red

### Cliente/servidor
- Uno o varios servidores.
- Los servidores proporcionan servicios.
- Los clientes utilizan esos servicios.
- Gestión centralizada.
- Recursos concentrados.
- Aporta control, seguridad y escalabilidad.

```text
        SERVIDOR
       /    |       CLIENTE CLIENTE CLIENTE
```

### P2P / grupo de trabajo
- Todos los equipos son iguales.
- Comparten recursos entre sí.
- No existe un servidor central.
- Sencillo, pero limitado en gestión.

```text
EQUIPO ←→ EQUIPO
   ↕         ↕
EQUIPO ←→ EQUIPO
```

### Comparación

| | Cliente/servidor | P2P |
|---|---|---|
| Gestión | Centralizada | No centralizada |
| Servidor central | Sí | No |
| Recursos | Centralizados | Repartidos |
| Ventaja | Control y escalabilidad | Sencillez |
| Uso | Organizaciones | Redes pequeñas |

## 7. Modos de instalación

### Instalación limpia
- Desde cero.
- No arrastra la instalación anterior.
- Requiere reinstalar servicios y restaurar datos.

### Actualización en el sitio
- Nueva versión sobre la anterior.
- Conserva configuración y datos.
- Solo entre determinadas versiones/ediciones.
- Requiere copia completa y probada.

### Migración
- Nuevo servidor.
- Se trasladan roles, datos y configuración.
- Permite mantener el anterior hasta comprobar el nuevo.

### Instalación paralela / laboratorio
- Máquina virtual.
- Permite probar antes de actuar sobre un sistema real.
