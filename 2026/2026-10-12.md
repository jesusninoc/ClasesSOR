# Administración de usuarios y grupos

## 2.1. Herramientas de gestión, permisos y derechos

### Explicar

El administrador debe gestionar:

- **Usuarios** → identifican a las personas o servicios que acceden al sistema.
- **Grupos** → permiten agrupar usuarios y aplicarles configuraciones comunes.
- **Permisos** → indican qué puede hacer un usuario o grupo sobre un recurso.
- **Derechos (privilegios)** → indican qué acciones puede realizar un usuario dentro del sistema.

### Windows Server

Herramientas habituales:

- **Usuarios y equipos de Active Directory** → gestión de usuarios y grupos del dominio.
- **Administración de equipos** → gestión local.
- `net user` → crear y gestionar usuarios.
- `net localgroup` → gestionar grupos locales.
- **PowerShell** → automatización y administración avanzada.

Ejemplos:

```powershell
net user ana /add
```

```powershell
net localgroup alumnos ana /add
```

### Linux

Herramientas habituales:

- `useradd` → crear usuarios.
- `usermod` → modificar usuarios.
- `userdel` → eliminar usuarios.
- `passwd` → establecer o cambiar contraseñas.
- `groupadd` → crear grupos.
- `groupdel` → eliminar grupos.

Ejemplos:

```bash
sudo useradd ana
```

```bash
sudo passwd ana
```

```bash
sudo groupadd proyectos
```

```bash
sudo usermod -aG proyectos ana
```

### Permisos frente a derechos

**Permiso:**

Indica qué puede hacer un usuario sobre un recurso.

Ejemplos:

- Leer un archivo.
- Modificar un archivo.
- Eliminar un archivo.
- Acceder a una carpeta.

**Derecho:**

Indica qué puede hacer un usuario dentro del sistema.

Ejemplos:

- Iniciar sesión.
- Apagar el equipo.
- Hacer copias de seguridad.
- Administrar usuarios.

### Linux: permisos `rwx`

En Linux los permisos básicos son:

- `r` → lectura.
- `w` → escritura.
- `x` → ejecución.

Ejemplo:

```bash
-rwxr-x---
```

Explicar que los permisos se aplican a:

- **Usuario propietario**.
- **Grupo propietario**.
- **Otros usuarios**.

Herramientas importantes:

```bash
chmod
```

Para modificar permisos.

```bash
chown
```

Para cambiar propietario y/o grupo.

```bash
sudo
```

Para ejecutar determinadas acciones con privilegios administrativos.

### Remarcar

- Los permisos deben concederse siguiendo el **principio de mínimo privilegio**.
- Siempre que sea posible, es mejor asignar permisos a **grupos** que directamente a usuarios.
- Un usuario puede pertenecer a varios grupos.
- Tener muchos privilegios aumenta el riesgo de errores y problemas de seguridad.

### Preguntas

- ¿Qué diferencia hay entre un permiso y un derecho?
- ¿Por qué es mejor asignar permisos a grupos?
- ¿Qué significan `r`, `w` y `x` en Linux?
- ¿Qué herramienta utilizaríamos para modificar permisos en Linux?

## 2.2. Automatización de la gestión con scripts

### Explicar

Cuando hay muchos usuarios, realizar las tareas manualmente resulta:

- Lento.
- Repetitivo.
- Fácil de hacer mal.
- Difícil de mantener.

Los scripts permiten automatizar tareas como:

- Crear usuarios.
- Eliminar usuarios.
- Crear grupos.
- Añadir usuarios a grupos.
- Cambiar contraseñas.
- Modificar propiedades de las cuentas.
- Deshabilitar cuentas.

### Windows

Se puede utilizar:

- CMD.
- PowerShell.

Ejemplo:

```powershell
net user alumno01 /add
net localgroup alumnos alumno01 /add
```

Con PowerShell también podemos automatizar procesos más complejos.

### Linux

La automatización suele realizarse mediante **Bash**.

Ejemplo:

```bash
sudo useradd alumno01
sudo usermod -aG alumnos alumno01
```

### Ventajas

- Ahorro de tiempo.
- Menos errores manuales.
- Resultados homogéneos.
- Procesos repetibles.
- Facilidad para administrar muchos usuarios.

### Remarcar

Automatizar no significa ejecutar el script y olvidarse.

Hay que:

1. Probar el script.
2. Comprobar los resultados.
3. Revisar errores.
4. Verificar que los usuarios pertenecen a los grupos correctos.

### Pregunta

- ¿Qué ventajas tendría utilizar un script para crear 100 cuentas de alumnos?

## 2.3. Tipos y ámbitos de los grupos

### Explicar

Los grupos permiten administrar usuarios de forma conjunta.

En lugar de asignar permisos individualmente:

```text
Ana → permiso
Luis → permiso
Pedro → permiso
María → permiso
```

podemos hacerlo mediante un grupo:

```text
Ana
Luis
Pedro
María
   ↓
Alumnos
   ↓
Permisos
```

Esto facilita mucho la administración.

---

### Tipos de grupos en Windows

#### Grupos de seguridad

Se utilizan para:

- Asignar permisos.
- Controlar el acceso a recursos.
- Aplicar políticas.

Son los grupos que debemos destacar desde el punto de vista de la administración de permisos.

#### Grupos de distribución

Se utilizan principalmente para:

- Distribución de correo.
- Listas de distribución.

No se utilizan para asignar permisos de seguridad.

---

### Ámbitos de los grupos en Windows Server

En un entorno de dominio podemos encontrar:

- **Local del equipo**.
- **Global**.
- **Local de dominio**.
- **Universal**.

No es necesario memorizar únicamente los nombres: hay que entender **dónde pueden utilizarse y qué usuarios pueden contener**.

### Estrategia habitual

Una idea importante para los alumnos es separar:

```text
CUENTAS
   ↓
GRUPOS GLOBALES
   ↓
GRUPOS LOCALES DE DOMINIO
   ↓
PERMISOS
```

La idea es evitar asignar permisos directamente a cada usuario.

### Linux

Linux no utiliza los mismos ámbitos de grupo que Windows.

Un usuario puede pertenecer a:

- Un **grupo principal**.
- Uno o varios **grupos secundarios**.

Para consultar los grupos:

```bash
groups ana
```

También podemos consultar la información del usuario:

```bash
id ana
```

### ⚠️ Error importante en Linux

Este comando:

```bash
usermod -G proyectos ana
```

puede **sustituir los grupos secundarios existentes** del usuario.

Para añadir el grupo sin perder los anteriores:

```bash
usermod -aG proyectos ana
```

### Pregunta

- ¿Qué ocurriría si añadimos a Ana a `proyectos` sin utilizar `-a`?

### Remarcar

La opción:

```text
-aG
```

debe quedar muy clara:

- `-G` → indica los grupos secundarios.
- `-a` → añade el nuevo grupo a los existentes.

**Idea para recordar:**

> `-G` puede sustituir; `-aG` añade.

## 2.4. Usuarios y grupos predeterminados y especiales

### Explicar

Los sistemas operativos incluyen cuentas y grupos que ya existen.

No deben modificarse ni eliminarse sin saber previamente qué función tienen.

Algunos son necesarios para:

- Administrar el sistema.
- Ejecutar servicios.
- Gestionar determinados recursos.
- Mantener el funcionamiento interno del sistema.

---

### Windows

Algunos usuarios y grupos habituales son:

- **Administrator** → cuenta administrativa.
- **Guest** → cuenta para invitados con privilegios limitados.
- **Administrators** → grupo de administradores.
- **Users** → usuarios normales.
- **Backup Operators** → usuarios con determinados privilegios relacionados con copias de seguridad.
- **Remote Desktop Users** → usuarios autorizados para utilizar Escritorio remoto.

### Remarcar

Pertenecer a determinados grupos puede proporcionar **muchos privilegios**.

Por ejemplo:

```text
Usuario normal
      ↓
Administrators
      ↓
Privilegios elevados
```

Por tanto, no debemos añadir usuarios a grupos administrativos sin una razón justificada.

---

### Identidades especiales de Windows

También existen identidades especiales que no funcionan exactamente como un usuario convencional.

Algunos ejemplos:

- `Everyone` → todos los usuarios que cumplen las condiciones correspondientes.
- `Authenticated Users` → usuarios autenticados.
- `Creator Owner` → propietario del recurso creado.
- `SYSTEM` → identidad utilizada por el propio sistema.
- `Interactive` → usuarios que han iniciado sesión localmente.
- `Network` → acceso realizado a través de la red.

### Preguntas

- ¿Qué diferencia hay entre un usuario normal y un administrador?
- ¿Por qué no debemos eliminar una cuenta del sistema sin conocer su función?
- ¿Qué riesgo tiene añadir un usuario al grupo `Administrators`?
- ¿Qué representa `Authenticated Users`?

---

### Linux

En Linux podemos encontrar:

- `root` → superusuario.
- Usuarios del sistema → utilizados por servicios y procesos.
- `nobody` → usuario con privilegios mínimos utilizado en determinados servicios.
- `sudo` / `wheel` → grupos utilizados para conceder privilegios administrativos, dependiendo de la distribución.

### Root

`root` tiene privilegios prácticamente ilimitados sobre el sistema.

Por eso:

- No debe utilizarse innecesariamente.
- Un error ejecutado como `root` puede afectar gravemente al sistema.
- Debemos utilizar privilegios administrativos solamente cuando sean necesarios.

### Remarcar

Los usuarios del sistema no necesariamente representan a personas.

Pueden existir para que un servicio funcione:

```text
Servicio
   ↓
Usuario del sistema
   ↓
Proceso
```

Por tanto:

> **No todo usuario del sistema es una persona.**

## 2.5. Revisión periódica de las cuentas y los grupos

### Explicar

La administración de usuarios no termina cuando se crea una cuenta.

Las cuentas y los grupos deben revisarse periódicamente.

Hay que comprobar:

- Cuentas que ya no se utilizan.
- Usuarios que ya no pertenecen a la organización.
- Usuarios con privilegios administrativos.
- Miembros de grupos sensibles.
- Cuentas antiguas.
- Cuentas temporales.
- Grupos que ya no son necesarios.
- Permisos asignados directamente a usuarios.
- Permisos excesivos.

### Pregunta

- ¿Qué problemas puede provocar mantener activada durante años una cuenta que nadie utiliza?

---

### Baja de un usuario

Cuando una persona abandona una organización, no siempre debemos eliminar inmediatamente su cuenta.

Una posible secuencia es:

1. Deshabilitar la cuenta.
2. Revisar sus grupos y privilegios.
3. Retirar los permisos que ya no sean necesarios.
4. Comprobar sus archivos y datos.
5. Realizar las copias necesarias.
6. Transferir la información a la persona correspondiente.
7. Eliminar la cuenta cuando ya no sea necesaria.

### Diferenciar

**Deshabilitar**

La cuenta continúa existiendo, pero no puede utilizarse normalmente.

**Expirar**

La cuenta deja de ser válida a partir de una fecha determinada.

**Eliminar**

La cuenta se borra del sistema.

### Remarcar

No debemos confundir:

```text
Deshabilitar ≠ Eliminar
```

Deshabilitar puede ser una medida temporal o de seguridad.

Eliminar es una acción más definitiva y puede provocar pérdida de información o dificultades para recuperar determinados datos.

## Ejemplo práctico: automatizar el alta de usuarios

### Situación

Una empresa o centro educativo necesita crear **80 cuentas de alumnos**.

Hacerlo manualmente implicaría:

- Crear 80 usuarios.
- Establecer sus contraseñas.
- Añadirlos a los grupos correspondientes.
- Comprobar cada cuenta.

Es una tarea repetitiva y propensa a errores.

### Solución

Crear un script que automatice el proceso.

### Ejemplo en Bash

```bash
for usuario in alumno01 alumno02 alumno03
do
    sudo useradd "$usuario"
    sudo usermod -aG alumnos "$usuario"
done
```

### Ejemplo en PowerShell

```powershell
$usuarios = "alumno01", "alumno02", "alumno03"

foreach ($usuario in $usuarios) {
    New-LocalUser $usuario
    Add-LocalGroupMember -Group "alumnos" -Member $usuario
}
```

### Explicar

El script:

1. Recorre una lista de usuarios.
2. Crea cada cuenta.
3. Añade cada usuario al grupo correspondiente.

La misma idea puede utilizarse para cientos o miles de cuentas.

### Remarcar

Antes de ejecutar un script de administración masiva:

- Probarlo con pocos usuarios.
- Comprobar los comandos.
- Revisar permisos.
- Verificar los resultados.
- Tener un procedimiento para corregir errores.

### Pregunta

> ¿Qué sería más eficiente para crear 500 cuentas: hacerlo manualmente o mediante un script?

La respuesta esperada es:

> **Mediante un script**, siempre que esté correctamente probado y se verifique el resultado.

# Ideas clave de la unidad

## Usuarios

- Representan identidades que pueden acceder al sistema.
- No todos los usuarios son necesariamente personas.
- Existen usuarios del sistema utilizados por servicios.

## Grupos

- Permiten administrar varios usuarios conjuntamente.
- Facilitan la asignación de permisos.
- Reducen la administración individual de cuentas.

## Permisos y derechos

- **Permiso** → qué puede hacer sobre un recurso.
- **Derecho** → qué puede hacer dentro del sistema.

## Windows

- Existen usuarios y grupos locales y de dominio.
- Los grupos pueden tener diferentes tipos y ámbitos.
- Los grupos de seguridad permiten asignar permisos.

## Linux

- Los usuarios tienen un grupo principal y pueden tener grupos secundarios.
- `r`, `w`, `x` representan lectura, escritura y ejecución.
- `chmod` modifica permisos.
- `chown` modifica propietario y grupo.
- `sudo` permite ejecutar determinadas acciones con privilegios elevados.

## ⚠️ Comando importante

No confundir:

```bash
usermod -G proyectos ana
```

con:

```bash
usermod -aG proyectos ana
```

**`-G` puede sustituir los grupos secundarios.**

**`-aG` añade el grupo conservando los anteriores.**

## Administración segura

- Aplicar el principio de mínimo privilegio.
- Evitar privilegios administrativos innecesarios.
- Revisar periódicamente usuarios y grupos.
- Deshabilitar cuentas que ya no deban utilizarse.
- No eliminar cuentas del sistema sin conocer su función.

## Automatización

- Los scripts permiten gestionar muchos usuarios rápidamente.
- Reducen tareas repetitivas.
- Disminuyen errores manuales.
- Deben probarse y verificarse antes de utilizarlos masivamente.

---

# Errores que quiero que recuerden

1. **Confundir permisos con derechos.**
2. **Dar permisos individualmente cuando se pueden gestionar mediante grupos.**
3. **Añadir un usuario a un grupo administrativo sin necesidad.**
4. **Eliminar cuentas del sistema sin conocer su función.**
5. **Confundir deshabilitar una cuenta con eliminarla.**
6. **Utilizar `usermod -G` cuando realmente queremos añadir un grupo.**
7. **Olvidar `-a` en `usermod -aG`.**
8. **Ejecutar scripts de administración masiva sin probarlos primero.**
9. **No comprobar el resultado de una modificación automatizada.**
10. **No revisar periódicamente las cuentas y los privilegios.**
